# Version 3.4 — Prediction Accuracy & Continuous Validation

Status: development; V3.3 production baseline remains unchanged.

## Highest-value objective
Build an immutable, prospective prediction archive and automated weekly scoring loop before expanding model complexity. Evaluate candidate prediction engines against identical games and prediction cutoffs; promote only verified improvements.

## Milestones
1. **Pregame forecast archive.** Capture game identity, teams, kickoff, prediction creation time, model and data version, predicted winner, probability, margin, and provenance. Use append-only/versioned records, deterministic game IDs, and idempotent scheduled writes. Never rewrite pregame predictions after kickoff. Flag missing or late forecasts; do not backfill as prospective.
2. **Automated grading.** Join finalized scores conservatively, retain FBS-vs-FCS coverage, exclude unrelated FCS-only fixtures from FBS performance denominators, reject duplicates and mismatches, and publish accuracy, Brier, log loss, calibration, and margin error with sample counts.
3. **Champion/challenger research.** Preserve V3.3 champion. Evaluate bounded candidate features (opponent adjustment, home field, preseason priors, recent form, FCS handling) on identical chronological splits; record paired metrics, uncertainty, and leak checks. Research must not silently replace production forecasts.
4. **Performance UI.** Show prospective versus retrospective evidence clearly, with weekly/season summaries, confidence buckets, model version and last-refresh timestamps; show 'insufficient data' instead of fabricated percentages.
5. **Release gates.** Deterministic archive/replay tests, duplicate and late-data cases, historical holdout validation, Python tests, frontend build, mobile/browser smoke, production Pages deploy and published-site smoke. Merge only after green checks.


## Coaching and scheme-matchup research (bounded challenger)
- Maintain dated head coach, offensive coordinator, and defensive coordinator assignments with tenure, previous jobs, and staff changes. Never use staff information learned after the forecast cutoff.
- Test head-coach performance **relative to opponent quality and preseason expectations**, not raw win rate or small head-to-head samples. Shrink sparse histories toward a neutral prior.
- Test observable offensive/defensive tendencies (tempo, run/pass, explosive plays, pressure/coverage where licensed data exists) and offense-vs-defense interaction features. Do not invent unobserved play-calling or proprietary scheme labels.
- Account for coordinator changes, roster strength, injuries and schedule confounding; avoid double-counting effects already captured by team ratings.
- Compare coaching/scheme challenger to the same V3.3 champion on identical pregame snapshots and chronological holdouts; report incremental Brier/log-loss and margin improvements with sample sizes. Promote only on robust evidence.
- Begin with staff assignment/provenance audit and one or two measurable matchup interactions, not a large manual coaching database.

## Non-goals
No large model rewrite, unsourced poll ingestion, unverified CFP accuracy claims, or cosmetic redesign. CFP and ranking improvements follow after the evaluation loop proves reliable.

## First implementation slice
Audit current data-refresh, report, prediction and historical-score paths; design minimal forecast record schema and immutable storage mechanism using existing GitHub Actions/data conventions. Add contract tests first, then one end-to-end archive→final score→graded report fixture. Ensure scheduled run timing respects kickoff and preserves prior snapshots.

## Definition of done
Prospective forecasts are automatically archived before kickoff and graded after final results; challenger evaluation is reproducible; the dashboard truthfully reports performance; V3.3 behavior is preserved unless a candidate passes independent validation; all CI and Pages release gates pass.
