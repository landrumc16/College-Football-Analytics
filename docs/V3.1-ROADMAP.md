# College Football Analytics — Version 3.1 release plan

Status: **release candidate** on `v3.1-development` (pending production Pages verification). Version 3 is the stable deployed baseline (Actions run 41516928308). Do not change the production prediction formula in 3.1.

## Objective
Make weekly refreshes dependable and make actual, timestamped pregame forecasts auditable. Never reconstruct historical pregame forecasts from postgame ratings.

## Delivery sequence
1. **Forecast ledger and provenance.** Archive pending-game predictions with generation time, source snapshot time, model ID and kickoff time *before* the game. Never overwrite the first valid pregame forecast; preserve later revisions separately only when explicitly timestamped. Reject missing/invalid timestamps, future-dated data, changed game identities, and post-kickoff forecasts. FBS–FCS predictions may be archived, but FBS–FBS accuracy is a distinct scorecard.
2. **Refresh reliability.** Check scheduled refresh workflow, artifact persistence, idempotent reruns, stale data and failure reporting. Ensure a failed refresh never publishes a misleading current report.
3. **Accuracy dashboard.** Show archived sample size, win accuracy, Brier, log loss, calibration and margin error only where actual archived inputs support each metric. Report missing coverage and model version. Separate retrospective studies from real pregame forecasts.
4. **Release gate.** Unit and integration tests for timestamp boundaries, reruns, aliases, FCS, partial games, and missing data; frontend build; mobile smoke; production Pages verification; rollback path. Merge only after passing.

## Operating cadence
Weekly in-season refresh and after-game evaluation; preserve every eligible pregame record. Time-box development; prioritize a working release over speculative modeling. Use the existing workbook baseline until a separately evaluated future release proves an improvement.

## Acceptance
- No postgame or retrospectively reconstructed prediction counted as pregame.
- No forecast silently lost or overwritten on refresh/retry.
- Data freshness and prediction sample coverage visible.
- All established Version 3 features remain functional.
- GitHub Actions and deployed site pass end-to-end.

## Release verification
- Full Python and frontend regression suites passed on development commit `91294bb` (four GitHub Actions workflows).
- Integration tests cover first pregame publication, idempotent revision, postgame evaluation, and stale snapshot rejection.
- Production Pages build must pass the existing live-data freshness gate, mobile browser smoke, and artifact equality check before release is considered complete.
- Rollback: revert the Version 3.1 merge commit on `main`, then rerun the Pages workflow. Preserve `data/pregame-2026-history.json` independently; never revert or discard newer archived forecasts.
