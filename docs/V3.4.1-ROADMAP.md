# Version 3.4.1 — Installable Progressive Web App Roadmap

Status: APPROVED ROADMAP / IMPLEMENTATION PENDING
Branch: `v3.4.1-development`
Base: released V3.4 on `main`
Production: https://landrumc16.github.io/College-Football-Analytics/

## Mission
Deliver an installable, mobile-first College Football Analytics experience on Android and iOS using the existing React/Vite dashboard and GitHub Pages deployment. Preserve existing rankings, predictions, CFP forecasts, schedules, matchups, research, and provenance. Do not create a separate native application or change prediction models in this release.

## Operating principles
Think before coding; keep changes small, maintainable, and testable. Work in large coherent implementation chunks, avoid redundant systems and unnecessary dependencies, and preserve working functionality. Do not reopen V3.4 modeling decisions. Keep the research library as the final dashboard section.

## Milestone 1 — App foundation
- Add a valid web manifest with name, short name, description, theme/background colors, display standalone, scope, start_url and suitable purpose-built 192x192 and 512x512 icons (including maskable artwork where practical).
- Integrate manifest and mobile platform metadata into the Vite app; ensure icon and asset URLs resolve from the GitHub Pages project subpath, not domain root.
- Ensure installation works without changing the canonical public URL and that the normal browser experience remains available.
Acceptance: production manifest and all icon URLs return successfully; Chrome/Android installation is offered when platform conditions permit; iOS Safari Add to Home Screen launches appropriately.

## Milestone 2 — Safe loading and update behavior
- Implement a minimal service worker only if needed for the desired install/update behavior. Prefer a proven small strategy; avoid adding complex caching infrastructure.
- Network-first for versioned app entry points or another strategy that guarantees users can get new releases; cache immutable hashed build assets only where safe.
- Never present cached scores, rankings, predictions or time-sensitive JSON as current. Prefer network-only for live data; show clear unavailable/stale indicators and timestamps if the network fails.
- Make updates available on next launch or refresh without requiring reinstall. Avoid disruptive mid-session reloads.
Acceptance: a new deployed version replaces the old UI on relaunch/refresh; unavailable live data is not silently substituted with stale results; offline states are understandable.

## Milestone 3 — Mobile app polish
- Use a recognizable college-football-themed icon and coherent splash/theme colors.
- Check standalone viewport, safe-area insets, touch target sizes, horizontal table scrolling, dropdown navigation, and the final collapsible Research & Data section.
- Preserve search autocomplete, ranking tables, game predictions, team schedule, matchup tool, CFP bracket, conference data and provenance warnings.
Acceptance: usable at representative small and large Android and iPhone widths, both browser and installed modes, without critical overflow or inaccessible controls.

## Milestone 4 — Automated verification and release
- Add automated manifest/icon/path checks and build tests. Extend existing browser smoke tests to check installed/standalone behavior where supported.
- Verify GitHub Pages base path, HTTPS, service-worker scope, cache behavior, and a simulated upgrade from the prior build.
- Run existing Python model tests and production dashboard checks. Do not weaken existing source-freshness, archived-prediction, or demo/live-data gates.
- Open a PR from `v3.4.1-development`, merge to `main` after checks, and verify production GitHub Pages deployment and actual served manifest/assets.
- Record release commit, workflow URL, public URL, test evidence, and known limitations in a closeout note.

## Definition of DONE (all mandatory)
1. Android users can install from the public website and launch via a named home-screen icon into an app-like standalone view (subject to browser install support).
2. iPhone users can add the site through Safari to their home screen and launch it with the intended icon and presentation (subject to iOS/browser behavior).
3. The app and ordinary browser share the same live GitHub Pages URL and codebase.
4. Subsequent website deployments update the installed experience on next launch/refresh; no manual reinstall is necessary.
5. No silent use of outdated scores or forecasts; offline/unavailable data is clearly labeled.
6. All V3.4 football pages and the collapsible Research & Data page still function and remain visually usable on mobile.
7. Automated model tests, web build, release validation and deployment pass.
8. Production manifest, icon resources, and service-worker scope (if used) are verified at the project subpath.
9. Release is merged to `main`, GitHub Pages deployment succeeds, and the published app is smoke-tested.
10. A concise installation guide for Android/iPhone and release closeout are committed.

## Explicitly out of scope
Native Android/iOS packages, Play Store/App Store publication, push notifications, user accounts, cloud sync, offline prediction computation, changes to the football model, and major new features. These can be assessed in future versions.

## Release shape
Complete the foundation and safe update strategy in one development pass, mobile/automated verification in a second pass, then merge, deploy, and close. Do not claim release complete based only on committed code or green unit tests; confirm the live published app.
